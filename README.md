# 楚河论弈 · 中国象棋模型竞技场

让两个大模型隔河对坐、实时对弈的中国象棋 Web 应用。红黑双方分别配置模型与 API Key，服务端负责棋规裁判和模型调度，前端以中国象棋棋盘实时直播整盘棋。顶部固定五个页签：**棋盘**、**自动评测**、**锦标赛**、**模型库**、**对局管理**。

## 功能介绍

### 棋盘

- 红黑双方独立配置模型，支持 OpenAI Chat Completions 兼容接口与 Anthropic Messages 接口；可直接选择模型库对象，也可临时填写配置。
- 实时观战：棋盘平滑走子，标记最后一步与被将军的将帅，实时显示双方状态、棋谱与吃子记录。
- 对局期间可暂停、继续、重试本回合或重新布阵；某方连续给不出合法着法时判负，对手获胜。
- 终局后显示胜方、终局原因与完整棋谱，可点击 **再来一局** 使用当前配置重新开始。

### 自动评测

- 添加 2–8 个模型配置，所有组合两两循环对弈；每对模型的对局数可设 1–20 局，红黑逐局轮换。
- 实时展示每个模型的胜 / 和 / 负、积分与排名，并可逐局查看结果。
- 评测可随时终止；模型 API 请求异常的对局单独记为「异常」，不参与积分。
- 模型数量与对局数会直接放大耗时和 API 费用，建议先用少量对局验证配置。

### 锦标赛

- 共 22 个参赛席位：种子池一至池三各 4 个直邀模型，加上 10 个入围赛模型。
- **入围赛**：10 个模型分入 A、B 两组（每组 5 人）进行组内单循环，共 20 局，每组前 2 名进入四号种子池。
- **随机抽签**：四个种子池分别洗牌，组合成 A–D 四组，保证每组恰好有来自四个池的各 1 个模型。
- **小组赛**：每组 4 人两两对弈一局，共 24 局，每组前 2 名进入八强。
- **淘汰赛**：八强、半决赛、决赛统一采用 6 局 3 分制，先到 3 分者晋级，红黑逐局轮换。
- 支持 1–8 路并发（默认 4）：入围赛按波次并行，小组赛按无共享选手的批次并行，淘汰赛同一轮系列赛并行。
- 每完成一局保存断点，服务重启或断电后可点击 **继续** 从未完成处续赛；每届赛事另存一份完整档案。
- 单届常规上限 86 局真实模型对局（入围赛 20 + 小组赛 24 + 7 场淘汰赛系列赛 × 最多 6 局）。

### 模型库

- 把模型名称、接口协议、模型 ID、Base URL、API Key、默认思考强度与推理参数开关保存为可复用对象。
- 支持新增、编辑、删除；编辑时可留空 API Key 保持原密钥，也可替换或清除密钥。
- 每个对象可直接 **测试** 接口、模型 ID 与密钥是否可用，显示延迟、Token 与回复预览；失败信息会脱敏。
- 内置 DeepSeek、OpenAI、Anthropic、Moonshot、智谱、OpenRouter、Ollama 等预设，也可完全自定义 Base URL 与模型 ID。
- 观战棋桌、自动评测和锦标赛的每个模型位都能直接选择已保存对象；锦标赛席位选择后自动采用模型库名称。

### 对局管理

- 自动归档观战对局、自动评测对局、入围赛与锦标赛对局，重启服务后仍可查看。
- 支持按来源、结果和模型关键词筛选，分页浏览；每页 20 条。
- 点击任意记录查看双方模型与思考强度、胜负与终局原因、起止时间、用时、Token 统计，以及完整着法列表（中文记谱、UCCI、落子理由、单步用时与 Token）。
- 详情面板内嵌只读棋盘，可逐手前进/后退、跳到首手/末手、自动播放、拖动进度条；点击棋谱任意一手直接跳转该局面。
- 可删除单条档案或清空全部，操作前二次确认；删除只影响本地档案。
- **锦标赛档案** 视图按届保存赛事，可回看四个小组的积分排名、淘汰赛对局图、每场系列赛比分与逐局结果；未完成的赛事标注为「已中止 / 异常中止 / 中断未续」。

### 比赛规则

- 使用标准 90 格棋盘，红方先行；文件 `a`–`i` 从左到右，横排 `0`–`9` 从红方底线向上。
- 完整棋子走法：马腿、象眼、九宫、炮架、过河兵、将帅照面；走完一步后若己方将帅被将军（含照面），该步非法。
- 无合法着法的一方判负：被将军为将死，否则为困毙。
- 自动终局优先级：将死/困毙 → 静态死局 → 三次重复 → 无进展死局 → 总手数达到 300 个半回合。
- **静态死局**：双方都已没有车、马、炮、兵/卒等进攻子力时立即判和。
- **无进展死局**：连续 60 回合（120 个半回合）没有吃子且没有兵卒推进，判和；吃子或兵卒推进会重置计数。
- 未实现官方竞赛规则中的长将/长捉裁判，娱乐对局采用上述简化判定。
- **计分**：自动评测与小组赛均为胜 3 分、和 1 分、负 0 分。自动评测排名依次比较积分 → 胜场 → 平局 → 报名顺序；小组赛在此基础上先比较相互对局积分，最后比较种子池位次。
- **6 局 3 分制**：淘汰赛每局胜方得 1 分、和局双方各得 1 分，先到 3 分者晋级；若同一局双方同时到 3 分（如三连和形成 3:3），进入加赛，此后先取胜的一方晋级；6 局封顶仍未分胜负时按小组排名裁决，排名完全相同则继续加赛至分出胜负。

### 调用协议

- 每一步向模型提供当前 FEN、可视棋盘、将军状态、近期着法与全部合法着法，模型只能从合法着法列表中选择。
- 支持两种协议：**OpenAI Chat Completions 兼容** 与 **Anthropic Messages**；Base URL 可填服务根路径或完整的 `/chat/completions`、`/messages` 端点。
- 请求为非流式，单步等待上限按思考强度为 60 / 120 / 240 秒；模型可用性测试超时上限 30 秒。
- 模型必须返回严格 JSON：`{"move":"h2e2","reason":"不超过当前思考强度限制的战略理由"}`。`move` 使用 UCCI 坐标，且只能从提示词给出的合法着法中选择。
- 服务端对返回值二次校验；非法或不可解析时带着合法着法列表重试，连续失败则判该方负，不直接落子。
- **思考强度**：OpenAI 协议模型可选择 `minimal / low / medium / high` 并默认发送对应 `reasoning_effort`，遇到不支持该参数的网关可关闭；Anthropic 模型可开启扩展思考并设置预算；也支持从模型 API 读取服务商提供的额外档位。
- API Key 只在本机使用：临时填写的 Key 仅驻留内存，模型库中的 Key 保存在本机且接口只返回末四位掩码，不进入日志、SSE 或历史档案。
- 常用接口：

| 提供商 | 协议 | Base URL | 模型示例 |
|---|---|---|---|
| DeepSeek | OpenAI 兼容 | `https://api.deepseek.com/v1` | `deepseek-chat` |
| OpenAI | OpenAI 兼容 | `https://api.openai.com/v1` | `gpt-4o-mini` |
| Anthropic | Anthropic Messages | `https://api.anthropic.com/v1` | `claude-sonnet-4-20250514` |
| Moonshot | OpenAI 兼容 | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| 智谱 | OpenAI 兼容 | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` |
| OpenRouter | OpenAI 兼容 | `https://openrouter.ai/api/v1` | `openai/gpt-4o-mini` |
| Ollama | OpenAI 兼容 | `http://127.0.0.1:11434/v1` | `qwen2.5:7b` |

### 并发机制

- 服务为单进程运行，同一时间只有一张棋桌、一场自动评测、一场入围赛和一场锦标赛。
- **自动评测** 按对阵顺序串行逐局运行。
- **入围赛与锦标赛** 支持 1–8 路并发，默认 4 路。
- **入围赛**：两组同时进行，每轮按「同一波次内没有共享选手」拆成 5 个波次，每波 4 局（每组 2 局），每位选手每波最多下一局。
- **小组赛**：24 局按 3 轮排成批次，同一批次内各局不共享选手，可并行执行。
- **淘汰赛**：同一轮的系列赛并行（八强 4 场、半决赛 2 场、决赛 1 场），单场系列赛内部逐局进行，不会并发落子。
- 并发越高越容易触发模型服务商的限流；遇到限流或超时可将并发调低。

## 使用方法

### 快速开始

要求 Node.js ≥ 22.12 与 npm。

```bash
npm install
npm run dev
```

打开 <http://127.0.0.1:4317>。

生产模式：

```bash
npm run build
npm start
```

服务默认只监听 `127.0.0.1:4317`。需要换端口或地址时：

```powershell
$env:PORT=4400; npm start
$env:HOST="0.0.0.0"; npm start   # 公开监听前请自行增加访问控制
```

### 棋盘

1. 打开顶部 **棋盘** 页签。
2. 在红方、黑方的 **模型库** 下拉框中选择模型；选择「临时配置（不保存）」则手动填写预设、Base URL、模型 ID 与 API Key。
3. 分别选择本局思考强度，按需调整「落子间隔」与「最大尝试次数」。
4. 点击 **开局**。对局期间配置锁定，可暂停、继续、重试本回合或重新布阵。
5. 终局后查看胜负、终局原因与完整棋谱；点击 **再来一局** 重新开始。

### 自动评测

1. 打开顶部 **自动评测** 页签，或访问 <http://127.0.0.1:4317/tournament>。
2. 添加 2–8 个参赛位，为每个参赛位选择模型库对象或临时配置；同一模型对象可用不同思考强度重复参赛，只需名称不同。
3. 设置每对模型的对局数（1–20），点击 **开始评测**。
4. 运行中实时更新积分榜与逐局结果；点击 **终止评测** 可随时停止。

### 锦标赛

1. 打开顶部 **锦标赛** 页签，或访问 <http://127.0.0.1:4317/championship>。
2. 在四号种子池页签配置 **入围赛**：10 个模型分入 A、B 两组（每组 5 席），点击 **开始入围赛**，每组前 2 名自动进入四号种子池。
3. 为种子池一至池三各配置 4 个直邀模型；可用「快速选择」从模型库勾选恰好 4 个模型一次性填满某个池，入围赛 A、B 两组也可各勾选 5 个模型快速填满。
4. 入围赛完成后点击 **随机抽签**：四个池分别洗牌，组合成 A–D 四组。
5. 点击 **开始锦标赛**，小组赛结束后前 2 名进入八强，随后进行半决赛与决赛。
6. 赛事进行中可点击 **终止锦标赛**；服务重启后可点击 **继续锦标赛** 从断点续赛。

### 模型库

1. 打开顶部 **模型库** 页签，或访问 <http://127.0.0.1:4317/models>。
2. 点击 **新增模型**，填写名称、接口协议、模型 ID、Base URL 与 API Key，可设置默认思考强度与推理参数开关。
3. 保存后可点击 **测试** 验证接口、模型 ID 与密钥是否可用；编辑时也可先点 **测试连接**，确认后再保存。
4. 在棋盘、自动评测和锦标赛的模型位中，都能直接选择已保存的模型对象。

### 对局管理

1. 打开顶部 **对局管理** 页签，或访问 <http://127.0.0.1:4317/admin>。
2. 页面顶部可在 **对局档案** 与 **锦标赛档案** 之间切换。
3. 对局档案支持按来源、结果和模型关键词筛选，分页浏览；点击记录查看详情，并在详情面板中回放棋谱。
4. 锦标赛档案可回看每届赛事的小组积分排名、淘汰赛对局图与系列赛比分。

### 棋盘观战

自动评测或锦标赛进行中，赛事页会显示「查看棋盘」入口，跳到当前对局的实时棋盘（<http://127.0.0.1:4317/watch>）。也可以直接指定 `mode` 与 `gameId` 打开某一场对局；最近一局结束后仍保留终局棋盘。

## 技术栈

- **语言**：TypeScript（严格模式），前后端共享类型定义。
- **前端**：React 19 + Vite 8，手写 CSS，无 UI 组件库；通过 SSE 接收服务端推送的实时状态。
- **后端**：Node.js 24 + Express 5，单进程运行；模型请求支持 OpenAI Chat Completions 与 Anthropic Messages 两种协议。
- **数据**：无需数据库，模型配置、历史档案与赛事数据以本地 JSON / JSONL 文件保存，重启后仍可查看与续赛。
- **测试**：Vitest，约 400 个用例覆盖规则引擎、模型适配与赛事流程；GitHub Actions 自动执行类型检查、测试与构建。
- **工具链**：npm、`tsc --noEmit` 类型检查、Vite 生产构建。

# 楚河论弈 · 中国象棋模型竞技场

让两个大模型隔河对坐、实时对弈的中国象棋 Web 应用。红黑双方分别配置模型与 API Key，服务端负责棋规裁判和模型调度，前端以中国象棋棋盘实时直播整盘棋。除观战棋桌外，还有 **模型库**、**自动评测**、**16 强锦标赛**、**对局管理** 四个独立页面。

## 功能

- **双模型对弈**：红方、黑方分别接入不同的模型，支持 OpenAI Chat Completions 兼容接口与 Anthropic Messages 接口；可从模型库选择，也可临时填写配置。
- **完整中国象棋规则**：马腿、象眼、九宫、炮架、过河兵、将帅照面、将军、将死、困毙；进入终局后立即停止模型请求并锁定结果。
- **自动终局判定**：将死/困毙判负；双方失去全部进攻子力、连续 60 回合无吃子且无兵卒推进、或达到 300 个半回合时判和。
- **实时观战**：棋盘平滑走子、标记最后一步与被将军的将帅，实时显示双方状态、棋谱与吃子记录；支持暂停/继续、重试本回合和重新布阵。
- **思考强度**：红黑双方可独立设置思考强度，影响提示词与推演要求；OpenAI 协议模型将自动发送对应的 `reasoning_effort`，Anthropic 模型可发送扩展思考参数。
- **模型库**：把模型名称、接口协议、模型 ID、Base URL、API Key、默认思考强度等保存为可复用对象，支持新增、编辑、删除；每个对象可直接测试接口、模型 ID 与密钥是否可用，显示延迟、Token 与回复预览。
- **自动评测**：添加 2–8 个模型配置，所有组合两两循环对弈，实时展示每个模型的胜 / 和 / 负、积分与排名；每对模型的对局数可设 1–20 局，红黑轮换。
- **16 强锦标赛**：先进行 10 人入围赛（A、B 两组各 5 人单循环，每组前二进入四号种子池），再把 16 个模型分入四个种子池、随机抽签分成四组，进行小组单循环与 6 局 3 分制淘汰赛，最终决出冠军。
- **断点续赛**：入围赛与锦标赛每完成一局都会保存进度，服务重启或断电后可点击「继续」从未完成处接着跑，已完成对局不会重赛。
- **对局管理**：自动归档已结束的观战对局、自动评测对局和锦标赛对局，支持按来源、结果、模型关键词筛选与分页浏览，查看终局原因、双方配置、用时、Token 与完整中文棋谱；可删除单条档案或清空全部。
- **锦标赛档案**：每届锦标赛保存一份档案，可回看四个小组的积分排名、淘汰赛对局图、每场系列赛比分与逐局结果。
- **棋盘观战与回放**：赛事进行中，可从赛事页一键跳到当前对局的实时棋盘；档案详情内可在棋盘上逐手回放整局棋谱。
- **本地优先**：无账号体系，模型配置、历史档案与赛事数据只保存在本机，密钥不会出现在浏览器存储、日志或归档中。

## 使用方法

### 快速开始

要求 Node.js ≥ 22.12 与 npm。

```bash
npm install
npm run dev
```

打开 <http://127.0.0.1:4317>。

生产模式：

```bash
npm run build
npm start
```

服务默认只监听 `127.0.0.1:4317`。需要换端口或地址时：

```powershell
$env:PORT=4400; npm start
$env:HOST="0.0.0.0"; npm start   # 公开监听前请自行增加访问控制
```

### 观战对局

1. 点击顶部固定页签 **模型库**，保存常用模型配置（可选；也可以直接临时填写）。
2. 在红方、黑方的 **模型库** 下拉框中选择模型；选择「临时配置（不保存）」则手动填写预设、Base URL、模型 ID 与 API Key。
3. 分别选择本局思考强度，按需调整「落子间隔」与「最大尝试次数」。
4. 点击 **开局**。对局期间配置锁定，可随时暂停、继续、重试本回合或重新布阵。
5. 终局后查看胜负、终局原因与完整棋谱；点击 **再来一局** 使用当前配置重新开始。

模型必须按提示返回严格 JSON：

```json
{"move":"h2e2","reason":"不超过当前思考强度限制的战略理由"}
```

其中 `move` 使用 UCCI 坐标，且只能从界面与提示词给出的当前合法着法列表中选择。服务端会二次校验，非法着法会带着合法列表反馈重试。

### 模型库

1. 打开顶部 **模型库** 页签，或访问 <http://127.0.0.1:4317/models>。
2. 点击 **新增模型**，填写名称、接口协议、模型 ID、Base URL 与 API Key，可设置默认思考强度与推理参数开关。
3. 保存后可点击 **测试** 发送一次最小请求，验证接口、模型 ID 与密钥是否可用；编辑时也可先点 **测试连接**，确认后再保存。
4. 在观战对局、自动评测和锦标赛的模型位中，都能直接选择已保存的模型对象。

### 自动评测

1. 打开顶部 **自动评测** 页签，或访问 <http://127.0.0.1:4317/tournament>。
2. 添加 2–8 个参赛位，为每个参赛位选择模型库对象或临时配置（同一模型可用不同思考强度重复参赛，只需名称不同）。
3. 设置每对模型的对局数（1–20），点击 **开始评测**。
4. 服务端按对阵顺序逐局运行，实时更新进度与积分榜；点击 **终止评测** 可随时停止。

计分规则：胜 3 分、平 1 分、负 0 分；排名依次比较积分、胜场、平局、报名顺序。模型 API 异常导致的失败局单独计入「异常」，不影响积分。

### 16 强锦标赛

1. 打开顶部 **锦标赛** 页签，或访问 <http://127.0.0.1:4317/championship>。
2. 在四号种子池页签配置 **入围赛**：10 个模型分入 A、B 两组（每组 5 席），点击 **开始入围赛**。两组同时进行组内单循环（每组 10 局、共 20 局），每组前 2 名自动进入四号种子池。
3. 为种子池一至池三各配置 4 个直邀模型。可直接从模型库选择，也可用「快速选择」从模型库勾选恰好 4 个模型一次性填满种子池；入围赛 A、B 两组各有一个「快速选择」按钮，勾选 5 个模型即可填满本组。
4. 入围赛完成后点击 **随机抽签**：四个种子池分别洗牌，组合成 A–D 四组，每组各有来自四个池的各 1 个模型。
5. 点击 **开始锦标赛**：小组单循环每对一局，每组前 2 名进入八强；八强、半决赛、决赛统一采用 **6 局 3 分制**（每局胜方 1 分、和局双方各 1 分，先到 3 分者晋级），最终决出冠军。
6. 赛事进行中可点击 **终止锦标赛**；服务重启后可点击 **继续锦标赛** 从断点续赛。

### 对局管理

1. 打开顶部 **对局管理** 页签，或访问 <http://127.0.0.1:4317/admin>。
2. 页面顶部可在 **对局档案** 与 **锦标赛档案** 之间切换。
3. 对局档案支持按来源、结果和模型关键词筛选，分页浏览；点击任意记录查看双方配置、终局原因、用时、Token 与完整着法列表。
4. 详情面板内嵌只读棋盘，可逐手前进/后退、跳到首手/末手、自动播放、拖动进度条，点击棋谱任意一手会直接跳转该局面。
5. 锦标赛档案可回看每届赛事的小组积分排名、淘汰赛对局图与系列赛比分。

### 棋盘观战

自动评测或锦标赛进行中，赛事页会显示「查看棋盘」入口，跳到当前对局的实时棋盘（<http://127.0.0.1:4317/watch>）。也可以直接指定 `mode` 与 `gameId` 打开某一场对局；最近一局结束后仍保留终局棋盘。

## 技术栈

- **语言**：TypeScript（严格模式），前后端共享类型定义。
- **前端**：React 19 + Vite 8，手写 CSS，无 UI 组件库；通过 SSE 接收服务端推送的实时状态。
- **后端**：Node.js 24 + Express 5，单进程运行；模型请求支持 OpenAI Chat Completions 与 Anthropic Messages 两种协议。
- **数据**：无需数据库，模型配置、历史档案与赛事数据以本地 JSON / JSONL 文件保存，重启后仍可查看与续赛。
- **测试**：Vitest，约 400 个用例覆盖规则引擎、模型适配与赛事流程；GitHub Actions 自动执行类型检查、测试与构建。
- **工具链**：npm、`tsc --noEmit` 类型检查、Vite 生产构建。
